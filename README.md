# Mobile Test Playground — API test framework

pytest + httpx functional tests, Pact consumer contracts and provider verification, and Allure
reporting for the **existing ShopTest backend** — the REST API behind the Mobile Test Playground app.

**API only.** This repository builds no mobile app, runs no UI test, needs no emulator or simulator,
and never modifies the backend.

| | |
|---|---|
| Backend under test | ShopTest API 0.1.0 (FastAPI + PostgreSQL), `../shoptest/backend`, run from its own `docker-compose.yml` |
| Python | 3.12 · pytest 9.1.1 · httpx 0.28.1 · pydantic 2.14.1 |
| Pact | pact-python 4.1.0 (Rust FFI, specification V4) |
| Allure | allure-pytest 2.16.2 · Allure 2 CLI 2.39.0 (checksum-pinned download) |
| Quality | Ruff 0.17.1 · mypy 2.4.0 `--strict` · gitleaks 8.30.1 |

## Quick start

```bash
uv sync --frozen                                        # pinned dependencies into .venv
BACKEND_DIR=../shoptest/backend scripts/backend.sh up   # the backend's own stack, ENVIRONMENT=testing
make test                                               # everything, one Allure report
make report-open                                        # view it
```

## Running

| What | Command |
|---|---|
| Functional API tests | `pytest -m functional` · `make functional` |
| Smoke subset (17 tests) | `pytest -m smoke` · `make smoke` |
| Pact consumer tests (no backend needed) | `pytest -m pact_consumer` · `make pact-consumer` |
| Pact provider verification | `pytest -m pact_provider` · `make pact-provider` |
| Consumer then provider | `make pact` |
| Everything | `pytest` · `make test` |
| Framework unit tests (no backend) | `pytest -m unit` · `make unit` |
| Lint, types, unit | `make check` |
| Random order (order-independence check) | `make test-random` |
| Secret scan | `make secrets-scan` |

The `make` test targets go through `scripts/run-tests.sh`: results in a run-specific directory, the
HTML report generated even when tests fail, and the **exit status is always pytest's**.

## Configuration

Environment variables (`MTP_*`), a gitignored `.env` (start from `.env.example`), or pytest options
(`--base-url`, `--target-env`, `--reset-mode`, `--run-id`). Defaults target
`http://localhost:8000` with the backend's documented seed accounts.

**Production is refused by default:** the base URL must be a recognisably non-production host
(loopback, private address, `.local`/`.test`, a Compose service name) or listed in
`MTP_ALLOWED_HOSTS`. Details: [docs/configuration.md](docs/configuration.md).

## How it works

- **Functional tests** (`tests/functional/`, 310 tests) make real HTTP requests through one client per
  resource and validate every response against strict, independently written models. Expectations —
  which products a filter returns, in which order, at what price — are computed from the backend's
  documented seed data. Coverage and gaps: [docs/api-coverage.md](docs/api-coverage.md).
- **Determinism:** `POST /test-data/reset` once per session; tests that consume stock reset before and
  after themselves; every write uses a freshly registered customer. Verified order-independent under
  two random orders.
- **Pact consumer tests** (`tests/contracts/consumer/`, 19 interactions) drive the framework's own
  clients against the Pact mock provider and write
  `pacts/MobileTestPlayground-Mobile-API-MobileTestPlayground-Backend-API.json`.
- **Provider verification** (`tests/contracts/provider/`) replays every contract against the real
  backend; a state-change server sets provider states through the API and injects per-instance UUIDs
  and tokens. The verifier's own result decides pass/fail; a missing contract is a failure.
- **Pact Broker** (optional): publish with version and branch, verify from the Broker and publish
  results, `can-i-deploy`, `record-deployment` — `python -m api_tests.pact.broker ...`.
  [docs/pact-workflow.md](docs/pact-workflow.md).
- **Allure:** suites API / Pact / Framework; every HTTP exchange is a step with a redacted, size-capped
  attachment; provider verification attaches contracts, provider-state changes and verifier output.
  [docs/allure-reporting.md](docs/allure-reporting.md).
- **Redaction:** one `Redactor` for logs, attachments, verifier output and Broker errors.
  [docs/security.md](docs/security.md).

### Pact consumer provenance

The contracts are a **Python model** of what the mobile clients need from the API. They do not prove
the Android or iOS networking code sends these requests: the Android app's Retrofit client currently
talks to an in-process interceptor with a different DTO shape and never calls this backend, and there
is no iOS client in the repository. Every pact file says so in its metadata. Contracts generated by
the real apps can be verified alongside via `MTP_PACT_EXTERNAL_DIR`.

## Backend findings

- **Defect:** `PATCH /admin/products/{id}` that would break the discount-below-price constraint
  answers 200 and echoes the change, but nothing is persisted.
- An incomplete address on `POST /orders` is reported as `error_payment_invalid`.
- Not implemented (so not tested): profile update, password change/reset, product reviews,
  save-for-later, admin order-status and user management, a version endpoint.

Full list: [docs/api-coverage.md](docs/api-coverage.md#findings-and-gaps).
